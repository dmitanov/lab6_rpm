Лабораторно-практическая работа №6

Тема: Структурные паттерны проектирования: Приспособленец, Заместитель, Мост, Декоратор


Выполнил: Митанов Д.В  Проверил: Макаров М. С.


Цель работы

Изучить структурные паттерны проектирования GoF на примере создания консольного приложения, имитирующего систему визуализации графических документов. В ходе выполнения работы необходимо освоить применение паттернов Flyweight для экономии памяти, Proxy для работы с тяжёлыми объектами через промежуточный класс, Bridge для разделения объектов и способов их отображения, а также Decorator для гибкого добавления новых свойств объектам во время выполнения программы.


Задание

Требовалось разработать консольную программу, которая моделирует рендеринг сложных документов, включающих текст, изображения и графические фигуры. Приложение должно обеспечивать:

экономичную работу с большим числом одинаковых объектов, например символов текста и их параметров, с использованием паттерна Flyweight;

ленивую загрузку изображений и управление доступом к ним через паттерн Proxy;

независимое развитие фигур и механизмов их отображения с применением паттерна Bridge;

возможность динамически расширять поведение объектов, добавляя к ним визуальные эффекты, такие как рамка, тень и прозрачность, через паттерн Decorator.


Теоретическое обоснование

Структурные паттерны проектирования применяются для более удобной организации связей между объектами и классами, а также для повышения гибкости архитектуры программы.

Паттерн Приспособленец (Flyweight) используется в тех случаях, когда в системе присутствует большое количество похожих объектов. Его задача состоит в том, чтобы хранить общее состояние один раз и переиспользовать его, не создавая одинаковые экземпляры повторно. В данной работе этот подход применяется для символов текста: одинаковые символы с одинаковыми параметрами шрифта не создаются заново, а берутся из фабрики уже готовых объектов.

Паттерн Заместитель (Proxy) вводит специальный объект, который контролирует доступ к основному объекту. Это удобно для ленивой загрузки, кэширования или ограничения доступа. В программе данный паттерн используется для изображений высокого разрешения, которые не загружаются сразу, а создаются только тогда, когда действительно нужны.

Паттерн Мост (Bridge) позволяет отделить абстракцию от её реализации, чтобы обе части можно было изменять независимо друг от друга. В рамках лабораторной работы это выражается в том, что фигуры и способы их отрисовки реализованы отдельно: одна и та же фигура может быть выведена, например, на экран или в режим печати.

Паттерн Декоратор (Decorator) нужен для того, чтобы расширять возможности объектов без изменения их исходного кода. Вместо создания множества подклассов можно обернуть объект в дополнительные классы-декораторы. В работе такой подход используется для добавления графическим объектам рамки, тени и прозрачности.

Применение этих паттернов делает систему более модульной, уменьшает жёсткую связанность между частями программы и упрощает её дальнейшее развитие.



Описание выполненной работы

В процессе выполнения лабораторной работы было создано консольное приложение, моделирующее работу системы рендеринга графических документов.

Сначала был реализован паттерн Flyweight. Для этого создан класс, описывающий символ текста. Общие характеристики символа, такие как сам знак, шрифт и размер, хранятся как внутреннее состояние, а координаты вывода передаются отдельно при использовании объекта. Также была создана фабрика, которая отвечает за хранение и повторное использование уже созданных символов.

Далее был реализован паттерн Proxy. Для работы с изображениями введён интерфейс изображения, класс реального тяжёлого объекта и класс-заместитель. Заместитель не создаёт настоящее изображение в момент своего появления, а делает это только при первом обращении к нему. Благодаря этому достигается отложенная загрузка ресурсоёмких объектов.

После этого был реализован паттерн Bridge. Был создан интерфейс механизма рендеринга, а затем несколько его реализаций, например вывод на экран и вывод в режиме печати. Отдельно были разработаны классы фигур, которые используют выбранный механизм отображения. Таким образом, фигуры и способы их визуализации существуют независимо друг от друга.

На последнем этапе был реализован паттерн Decorator. Для этого создан базовый декоратор и несколько его конкретных вариантов, которые добавляют объектам дополнительные визуальные свойства. В результате любой графический элемент можно во время работы программы дополнить рамкой, тенью или прозрачностью без изменения его основного класса.

В методе Main была организована демонстрация всех реализованных паттернов: показано повторное использование объектов символов, отложенная загрузка изображений, работа фигур с разными способами отображения и применение декораторов к графическим объектам.



Результаты работы

В результате выполнения лабораторной работы было разработано консольное приложение, демонстрирующее использование структурных паттернов проектирования при создании системы рендеринга графических документов.

Проведённая проверка показала, что применение паттерна Flyweight позволяет уменьшить количество однотипных объектов и тем самым сократить затраты памяти. Использование Proxy даёт возможность не загружать тяжёлые изображения заранее, что положительно влияет на производительность. Паттерн Bridge обеспечивает независимость между фигурами и способами их отрисовки, благодаря чему архитектура становится более гибкой. Применение Decorator позволяет добавлять объектам новые свойства без изменения существующего кода и без избыточного наследования.

Таким образом, поставленная цель работы была достигнута, а использование структурных паттернов показало свою эффективность при проектировании расширяемого и удобного в сопровождении программного обеспечения.
